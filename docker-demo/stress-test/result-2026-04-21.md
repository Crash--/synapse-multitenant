## F#2 — room-based createRoom workload

The 2026-04-20 baseline noted: `createRoom` reliably returned HTTP 500 due to the state-group schema leak, forcing the stress test to run only the room-free variant. **This failure is now closed.**

Validation:

1. Manual 1-room-per-tenant verification during bootstrap — all 4 return 200 with correct `room_id`s ending in the tenant's server_name.
2. **20-way concurrent `createRoom` burst** (5 users × 4 tenants in parallel) — all 20 succeed. Post-run DB state:

   ```
   public.rooms                   | 0      ← no leaks
   public.state_groups            | 0      ← no leaks
   tenant-a/b/c/d.rooms           | 6 each (24 total)
   sum(tenant-{a..d}.state_groups) | 192   (24 rooms × 8 state_groups)
   ```

3. **Zero strict-mode assertions** during the full 5-minute 200-VU stress run + the 20-concurrent burst. `SYNAPSE_MT_STRICT_STATE_GROUPS=1` was on throughout. Any state-group write without an active tenant context would have raised `AssertionError`; none did.

## Permanent instrumentation committed

Task 6 landed DEBUG logs + env-gated assertions in the state-persistence path (`state/store.py`, `state/deletion.py`, `database.py::_set_tenant_schema`). These are not scaffolding — they remain as durable guards. CI can enable `SYNAPSE_MT_STRICT_STATE_GROUPS=1` to fail fast on any future regression that reintroduces writes without tenant context.

## Deferred follow-ups

- **F#1 audit tier 2**: 14 more `@cached` / `@cachedList` decorators surfaced by the audit at `docs/multi_tenant/cache_audit.md` but kept out of scope for this PR (federation destinations, server_keys_json, instance_map, stream-token-only keys, zero-arg MAU counts, `get_partial_rooms`). Each is a same-class leak; a follow-up PR should walk through them with the same TDD pattern.
- **Worker-path invalidations**: the replication-row invalidation sites at `synapse/storage/databases/state/store.py:129-130` and `events_worker.py:461` silently no-op on tenant-scoped caches when invoked without an active tenant context. Not live today (no per-tenant workers), but must be tenant-contextualized before a workers deployment mode ships.
- **Cross-tenant cache invalidation reach**: `@tenant_cached`'s `.invalidate` wrapper auto-prepends the current tenant. Global-sweep invalidations (e.g. during a `/reload` cascade) must go through `.cache.invalidate(...)` directly if they need to reach other tenants' entries.
